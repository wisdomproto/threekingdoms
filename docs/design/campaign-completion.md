## 구현 계약

형주 확보, 입촉, 한중은 공통 구간. 본선은 연의의 인물 생애와 사건 순서를 지키고, 패전은 탈출·철수 엄호 등의 전술 목표를 달성한 뒤 후일담에서 결과를 설명한다. 플레이어의 패배 화면으로 다음 장을 강제하지 않는다.

장수 선택은 전투별 출전 가능 명단을 사용한다. 후반에 죽은 인물이 나오거나 적장과 같은 인물이 양쪽에 배치되는 것을 금지한다. 편성 후보, 출진 페이로드, 저작도구 저장 모두 같은 필드를 보존한다.

맵은 자체 격자와 새 회화형 바닥, 기존 지형·오브젝트 에셋을 함께 사용한다. 성곽 8곳은 포장된 넓은 광장과 지붕 없는 열린 입구를 갖추며, 벽은 충돌 격자에서 별도 렌더링한다. 신규 평상복 배우는 전투복과 분리한다.

전투 이벤트의 안내는 실제 피해·날씨·증원과 같은 트리거에서 실행한다. 전투 종료 후 뒤늦게 화공 대사를 재생하지 않는다. 새 전투는 시드 기반 자동 전투로 통행·목표·진행 가능성을 검사한다.

## 재생성과 데이터 설치

작성 원문: `tools/content/sequel-scenes.json`. `python tools/content/sequel-campaign.py`는 원문에서 저장소 데이터를 재생성한다. 저장된 Studio 프로젝트는 자동으로 바꾸지 않는다.

전체 재생성 순서: `sequel-campaign.py` → `sequel-city-art.py` → `pack-sequel-art.py` → `pack-sequel-settings.py` → `sequel-story-scenes.py` → `audit-sequel-art.py`. 연결 서술 원문은 `sequel-interludes.json`, 생성 프롬프트는 `docs/art/sequel-v1/`에 있다. 생성 원본 `.studio/sequel-art/sources`는 로컬에만 보관하고 런타임 WebP와 라이브러리를 배포한다. 소스 PNG가 없는 환경에서는 패킹을 다시 하지 않고 배포된 WebP를 사용한다.

이미 후반부가 설치된 프로젝트는 `pnpm --filter @tk/sim exec tsx ../../tools/content/refresh-sequel.ts <project-id> <검토한-revision>`으로 후반 장면·맵을 갱신한다. 백업과 revision 충돌 검사를 거치며 다른 MOD에는 적용하지 않는다.

`pnpm --filter @tk/sim exec tsx ../../tools/content/install-sequel.ts <project-id> --activate`는 기존 전체 캠페인에 없는 후반 챕터만 추가하고 로컬 게임에 반영한다. 사전에 백업하며 수정 충돌은 중단한다. 다른 MOD에는 적용하지 않는다. 원본 에셋/서버 데이터는 커밋하지 않는다.

Railway의 기존 seed 묶음은 확장 이전 데이터이므로 실제 배포 직전에 새로 패킹해야 한다. 이 작업에서 원격 배포나 push는 하지 않았다.
