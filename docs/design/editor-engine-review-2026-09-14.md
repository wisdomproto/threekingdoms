# 기존 저작도구·전투 엔진 검토 — 2026-09-14

현재 작업 트리의 기존 코드에 대한 검토다. Studio 연결은 진행 중이며 이번 검토에서 완료했다고 판단하지 않는다. 제품 전체 인수검사나 브라우저 UX 전수 검사가 아닌, 저장·게시와 전투 상태 전이 중심의 코드 검토 및 합성 입력 재현이다.

## 판단

기존 엔진과 편집기는 재사용 가치가 있다. 엔진의 UI 분리, 시드 기반 RNG, 행동 결과 이벤트, 시뮬레이터, 편집기 I/O·히스토리·저장 상태기계의 분리는 좋은 기반이다. 다만 기존 27개 콘텐츠를 실행하는 게임과 임의 콘텐츠를 안전하게 만드는 범용 저작도구 사이에는 검증 공백이 있다. 통합 전에 저장 손실과 유닛 식별 문제를 먼저 막아야 한다.

## 확인한 문제

### P1 — 게시·삭제가 더 최신 Draft를 지울 수 있음

- 위치: `tools/serve.py:351`, `tools/serve.py:457`, `tools/stage-editor.html:421`.
- 게시와 Draft 저장은 별도 잠금을 사용한다. 게시 검사 중 Draft revision 2가 저장돼도 게시 성공 후 `_delete_draft(stage_id)`가 최신본까지 삭제한다.
- `_draft_delete`도 baseRevision을 비교하지 않는다. 오래 열린 탭에서 원본까지 Undo하면 다른 탭의 최신 Draft를 지울 수 있다.
- 격리된 임시 디렉터리에서 기존 서버 함수를 실행했다. revision 1 게시 중 검사 함수에서 revision 2 저장을 끼워 넣자 게시본은 revision 1 내용이고 revision 2 파일은 삭제됐다. revision 2에 baseRevision 1 삭제 요청도 HTTP 200으로 성공했다.
- 수정 방향: 게시 스냅샷의 revision을 전달하고 해당 revision의 Draft만 조건부 삭제한다. 일반 삭제도 같은 비교를 잠금 안에서 수행한다. revision은 삭제·재생성 후에도 오래된 요청을 구분할 수 있어야 한다.

### P1 — 중복 장수 ID를 실행하면 두 유닛이 함께 변경됨

- 위치: `packages/engine/src/createBattle.ts:83`, `packages/engine/src/actions.ts:22`, `tools/stage-editor.html:1275`.
- 엔진 유닛 ID는 commander ID다. 편집기는 좌표 중복은 막지만 다른 좌표에 배치된 같은 commander ID는 거부하지 않는다. StageSchema도 허용한다.
- 같은 간옹을 (2,4), (1,4)에 배치한 합성 Stage가 스키마를 통과했다. 간옹 이동 1회 후 둘 다 (2,5)가 됐다. `replaceUnit`이 같은 ID를 전부 교체하기 때문이다.
- 수정 방향: 현재 엔진 계약에서는 실행 전 중복 commander ID를 차단한다. 같은 캐릭터의 여러 인스턴스를 허용하려면 instance ID와 commander ID를 분리하고 목표·일기토·증원·리플레이 참조를 함께 바꿔야 한다.

### P2 — 책략 격파에 경험치·콤보 처리가 빠짐

- 위치: `packages/engine/src/actions.ts:639` 이후 책략 분기.
- 일반 공격과 필살에는 `grantExp`와 `registerComboKill`이 있지만 책략 피해 경로에는 없다.
- 간옹이 업화로 병력 1인 화웅을 격파하고 다른 적은 생존하도록 구성했다. 격파 이벤트는 나왔지만 간옹 경험치 0→0, 레벨 1, 콤보 0, 보상 배열은 빈 상태였다.
- 문서의 행동 기반 성장 및 아군 연속 격파 보상과 맞지 않는다. 책략 위주 캐릭터의 성장이 막힐 수 있다. 회복·날씨 행동의 경험치 양은 별도의 규칙 결정이 필요하다.
- 수정 방향: 피해·격파 후 성장과 보상을 공통 처리하고 AoE 대상별 적용 및 중복 지급 방지를 검증한다. 변경 후 밸런스 게이트를 다시 실행한다.

## 구조적 제약

- 기존 편집기 저장 방식이 통일돼 있지 않다. Stage는 서버 Draft/Publish, 캐릭터 등은 파일 핸들·다운로드 흐름을 사용한다.
- 캠페인과 데이터 목록은 코드에 고정 등록돼 있다. 새 Stage JSON 저장만으로 신규 챕터가 게임에 자동 편입되는 구조가 아니다. Publish UI에도 신규 파일의 index 등록 필요 경고가 있다.
- Stage의 미지원 필드 보존 장치는 있지만 Map I/O는 알려진 필드로 재구성한다. 향후 맵 메타데이터 확장 시 무손실 보존을 별도로 다뤄야 한다.
- 권장 방향은 기존 상세 편집기를 재사용하고 Project 저장·실행 검증·리소스 참조 계약을 공통화하는 것이다.

## 후속 수정

사용자의 진행 요청으로 세 문제를 수정했다. Draft 삭제는 revision 비교 후 실행하며, 게시 검사 중 더 최신 저장이 생기면 그 Draft를 보존한다. 삭제 후에도 revision 상한을 별도 파일에 유지해 오래된 요청이 재생성된 Draft를 덮지 못하게 했다. 이전 클라이언트의 revision 없는 게시 요청은 Draft를 삭제하지 않는다. 삭제 응답 중 추가된 로컬 편집도 저장 완료로 오인하지 않도록 했다.

중복 장수는 편집기 실행 검증, Stage 스키마, 엔진 초기화에서 차단한다. 초기 배치와 증원 전체가 대상이다. 중복을 허용했던 기존 증원 테스트 두 개는 서로 다른 장수를 사용하도록 바로잡았으며, 중복 거부 회귀 테스트를 추가했다. 공격 책략은 대상별 경험치와 아군 격파 콤보를 지급하고, 범위 책략의 능력치는 시전 시작 기준으로 고정한다.
